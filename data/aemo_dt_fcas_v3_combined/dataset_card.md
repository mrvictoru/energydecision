# AEMO Battery Trading Dataset

Offline reinforcement learning dataset for battery energy storage trading in
Australia's National Electricity Market (NEM). Two files are available:

| File | Episodes | Rows | Source |
|------|:--------:|:----:|--------|
| **`aemo_fcas_dataset.parquet`** | 2,401 | 76.9M | SB3 policies (PPO, TD3, A2C, DDPG, SAC, FCAS rule) |
| **`aemo_fcas_v3_combined.parquet`** | 1,800 | 11.9M | GRPO-tuned Decision Transformer (Phase 1) |

The v3 data was generated by a GRPO-tuned DT model (post-trained from the
v2 pretrained DT) as an **experimental / historical** attempt to capture
improved FCAS bidding behaviour beyond what the SB3 models learned through
online RL. GRPO fine-tuning was later shown not to improve the modern v2
model, so this corpus is retained for provenance only (see the archived
banner at the top).

## Dataset Structure

Both files have the same Parquet schema with 6 columns:

| Column | Type | Description |
|--------|------|-------------|
| `step` | Int64 | Timestep index within the episode |
| `norm_observation` | List(Float32) | Normalised 18-dim state vector (see below) |
| `action` | List(Float32) | 9-dim action: energy dispatch + 8 FCAS bids |
| `reward` | Float32 | Step reward (energy + FCAS revenue − degradation cost) |
| `episode_id` | Int32 | Unique episode identifier |
| `source_policy` | String | Policy that generated the episode |

### State Space (18-dim)

Normalised AEMO market features — energy price (RRP), FCAS prices
(REG, 6s, 60s, 5min for raise/lower), solar/wind generation as % of capacity,
total demand, battery state of charge, time features (hour sin/cos,
day sin/cos, is_peak), battery flow.

### Action Space (9-dim, `full_fcas` mode)

| Dim | Description | Range |
|:---:|-------------|:-----:|
| 0 | Energy dispatch (−1 = charge, +1 = discharge) | [−1, 1] |
| 1–8 | FCAS service bids (8 services: RAISEREG, LOWERREG, RAISE6SEC, LOWER6SEC, RAISE60SEC, LOWER60SEC, RAISE5MIN, LOWER5MIN) | [0, 1] |

## Battery Configurations (both files)

Four battery variants matching real-world Australian BESS stations:

| Battery | Capacity | Max Power | C-rate | Duration | Real-world match |
|---------|:--------:|:---------:|:------:|:--------:|:-----------------|
| `medium_1c` | 10 MWh | 10 MW | **1.0C** | 60 min | Torrens Island, Waratah, Lake Bonney |
| `large_07c` | 50 MWh | 35 MW | **~0.7C** | 86 min | Hornsdale, Victorian Big Battery |
| `small_05c` | 2 MWh | 1 MW | **0.5C** | 120 min | Kennedy Energy Park (legacy) |
| `fast_375c` | 8 MWh | 30 MW | **3.75C** | 16 min | Dalrymple North BESS |

Distribution: `medium_1c` 40%, `large_07c` 25%, `small_05c` 20%, `fast_375c` 15%.

## Source Policies (v2 — SB3)

| Policy | Episodes | Description |
|--------|:--------:|-------------|
| PPO | 900 | Proximal Policy Optimisation |
| TD3 | 300 | Twin Delayed DDPG |
| A2C | 300 | Advantage Actor-Critic |
| DDPG | 300 | Deep Deterministic PG |
| SAC | 300 | Soft Actor-Critic |
| FCAS rule | 300 | Percentile-based FCAS bidding heuristic |

All SB3 models trained on combined 5-region data with all 4 battery
configurations at 5-minute resolution (200K timesteps each).

## Source Policies (v3 — GRPO)

| Policy | Episodes | Description |
|--------|:--------:|-------------|
| GRPO DT (short) | 900 | Phase 1 GRPO-tuned DT, 12-day episodes |
| GRPO DT (medium) | 900 | Phase 1 GRPO-tuned DT, 8-week episodes |

Both generated from the same GRPO model with `rtg_value=0.5`, `dt_gamma=0.95`,
across all 4 battery configurations and 5 NEM regions.

## Data Generation

**v2 (SB3):**
```bash
python3 scripts/retrain_sb3_full_fcas.py --algorithms PPO,A2C,DDPG,SAC,TD3
python3 scripts/generate_fcas_dataset.py --policies ppo,td3,a2c,ddpg,sac,fcas_rule
python3 scripts/generate_fcas_dataset.py --mode assemble
```

**v3 (GRPO) — historical:** The `generate_grpo_episodes.py` command shown in
older notes does not exist in the current tree and is **not** a runnable CLI
entry point. GRPO post-training is implemented in `src/grpo_posttraining.py`
(entry points `scripts/run_grpo_posttraining.py` and
`scripts/run_grpo_multi_region.py`); the experiment record — a negative
result, GRPO did not improve the modern v2 model — is in
`docs/grpo_experiments.md`. This GRPO corpus is historical and superseded
(see the archived banner at the top).
