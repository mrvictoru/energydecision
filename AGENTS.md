## Repo structure quirks

- **Single package, flat namespace.** No `setup.py` or `pyproject.toml`. `src/` has no `__init__.py` — files import each other directly (`from EnergySimEnv import SolarBatteryEnv`).
- **Tests** access `src/` via `sys.path.insert(0, ...)` in `tests/conftest.py` — no `PYTHONPATH` needed.
- **No linter, formatter, CI, coverage, or Makefile.** Only `pytest.ini`. Run `python -m pytest tests/ -v` for full suite.

## Runtime paths: Distrobox vs Docker

- **Distrobox (preferred)**: run from repo root → `python3 src/...`, paths are `data/...`, `models/...`
- **Docker Compose**: workdir is `/code/src` → scripts are bare names, paths use `../data/...`
- If paths feel wrong, check which runtime is active.

## Key empirical findings (don't waste time rediscovering)

| Finding | Detail |
|---------|--------|
| **Best DT hyperparams (expanded eval)** | 8×512, ctx=180, drop_p=0.15, batch=16, lr=3e-5, epochs=2, discount=0.95, return_scale=2.0 |
| **Best DT hyperparams (FCAS-rich)** | 8×384, ctx=180, drop_p=0.15, batch=64, lr=3e-5, epochs=2, discount=0.95, return_scale=2.0 |
| **Context sweep** | ctx=180 best on pilot data. Longer ctx (288, 576, 1008) regressed. ctx=2016 is now feasible with 22GB (retest with FCAS data). |
| **Proxy metric** | AEMO proxy tier: `best_val_action_loss` (lower better). Broader tiers: `best_val_total_loss`. |
| **RTG matters** | Evaluate with multiple rtg values (0, 5, 10, 15, 20). The DT responds to RTG prompt. |
| **FCAS gap closed** | On FCAS-rich data: DT earns $1,383/ep FCAS (18× improvement from $77/ep). PPO earns $1,616/ep. Gap is now 14%, not 138×. |
| **Loss weights (June 2026)** | Grid sweep found `action_loss_weight=0.999, state_loss_weight=0.002, return_loss_weight=0.0001` gives best evaluator results (mean_reward > 0 on mini evaluator). Near-zero state/return weights mean the model focuses almost entirely on action prediction accuracy. |
| **Batch size** | 16 is the sweet spot for 8×512 on this hardware. |
| **Checkpoint resume** | --context-length must match checkpoint. |

## Autoresearch evaluator (sim-run validation)

The autoreasearch evaluator validates DT checkpoints in held-out sim environments, not just validation loss.
Three evaluator configs balance speed vs. breadth:

| Config | Use | Step | Hours | Regions | Batteries | Baselines | Workers | 24h wall clock |
|--------|-----|------|-------|---------|-----------|-----------|---------|----------------|
| `mini` | Smoke / quick screening | 5 min | 24h | NSW1, SA1 | medium | DT, FCAS rule | 4 | ~2 min |
| `example` | Promotion check | 30 min | 144h | NSW1, SA1, QLD1, VIC1 | medium, small | DT, rule, FCAS rule, 2×dispatch, PPO | 8 | ~15 min |
| `expanded` | Full season sweep | 30 min | 288h | All 5 regions × 6 months | medium | DT, rule, PPO | 8 | ~60 min |

**Usage by tiner:**
- `proxy-baseline` → `mini` (after training, wrapped by `launch_aemo_training.py`)
- `learning-baseline` → `example` (after training)
- Standalone: `python3 src/autoresearch_evaluator.py --surface-manifest-path <path> --evaluation-config configs/aemo_autoresearch_evaluator.{mini,example}.json --output-dir <dir>`

**The `mini` evaluator now uses `fcas_rule` as the reference baseline** (replacing old `rule`).
The paired comparison reports `candidate_dt vs fcas_rule`, revealing whether the DT learned FCAS bidding.
Old `rule` is still included in the `example` and `expanded` configs for historical comparison.

**Cache:** Non-DT policy rollouts are cached in `eval_output/autoresearch/reference_cache/`.
Prewarming: `python3 src/prewarm_aemo_cache.py --evaluation-config configs/aemo_autoresearch_evaluator.{mini,example}.json`

## FCAS rule algorithm

`AEMOAgent(algorithm='fcas_rule')` in `decision.py` extends the original rule with percentile-based FCAS bidding.

**How it works:**
- Energy dispatch: same as original rule (charge ≤ $30, discharge ≥ $120, SOC guardrails)
- FCAS bidding: bids 1.0 on RAISEREG/LOWERREG when the current price exceeds a data-driven percentile threshold (default p80) and SOC headroom permits
- Thresholds computed from env's own `aemo_data` at agent init — no model, no training

**Usage:**
```python
agent = AEMOAgent(env, algorithm='fcas_rule', fcas_pctile=0.80)
```
Can also set explicit thresholds:
```python
agent = AEMOAgent(env, algorithm='fcas_rule',
                  fcas_raise_threshold=30.0, fcas_lower_threshold=25.0)
```

**Performance (NSW1, 12-day, medium):** $2,941 FCAS rev / ep (vs $0 for original rule)

## Data generation pipeline

`src/generate_fcas_dataset.py` generates FCAS-rich episodes from both SB3 models and the FCAS rule.
```bash
# Generate FCAS rule episodes
python3 src/generate_fcas_dataset.py --policies fcas_rule

# Generate from SB3 models
python3 src/generate_fcas_dataset.py --policies ppo,td3,a2c,ddpg,sac

# Assemble final dataset (after all generation)
python3 src/generate_fcas_dataset.py --mode assemble
```
Output: `data/aemo_dt_fcas/aemo_fcas_dataset.parquet`

`src/convert_dispatch_to_episodes.py` converts raw AEMO DISPATCHLOAD + DISPATCHPRICE data directly into episode logs without running the simulator environment. Unlike the legacy `generate_dispatch_replays.py` (energy-only), it captures **all 8 FCAS services** from actual AEMO-cleared values and computes revenue using historical market prices:
```bash
python3 src/convert_dispatch_to_episodes.py \
    --station dalrymple_north \
    --start-date 2024-01-01 \
    --end-date 2024-07-01 \
    --output data/aemo_dispatch_episodes/dalrymple_north_2024h1.parquet
```
